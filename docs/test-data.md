# Тестовые данные

Пока нет реальных выгрузок, работаем на синтетических данных в двух форматах:

| Набор | Где лежит | Формат |
|---|---|---|
| Выгрузка из 1С | `data/samples/onec/*.json` | OData 1С (`standard.odata`) |
| Подготовленная база конкурентов | `data/samples/prepared/prepared.sqlite` | SQLite, «сырые» данные после парсинга |

Данные воспроизводимы: `market-map generate-samples` с тем же seed всегда даёт те же файлы.

```bash
market-map generate-samples                 # → data/samples
market-map generate-samples --out /tmp/x --seed 42
```

Эти форматы — **контракт для загрузчиков**. Когда придут реальные данные, они либо приводятся к этому формату, либо для них пишется адаптер.

## Легенда

**Своя компания** — дистрибьютор стройматериалов (бренды ПрофМикс, ГидроСтоп, Тёплый Дом). Работает в 10 регионах: Москва, Московская обл., Санкт-Петербург, Нижегородская обл., Татарстан, Самарская обл., Свердловская обл., Новосибирская обл., Краснодарский край, Ростовская обл.

- **Клиенты** (33) — покупатели своей компании в каналах: дистрибуция, опт, DIY-сеть, строительная компания, розница, маркетплейс.
- **Номенклатура** — 25 товаров в 5 группах: сухие смеси, клеи и затирки, гидроизоляция, грунтовки, утеплители.
- **Конкуренты** (15) продают:
  - **идентичный товар** — те же бренды, тот же артикул;
  - **схожий товар** — аналоги брендов БазаМикс, Кварц, АкваБарьер, ТермоЛайн.

Все названия компаний, ИНН и сайты вымышленные (домены `.example`).

## Формат 1С (OData)

Каждый файл — ответ OData: `{"odata.metadata": "...", "value": [ ... ]}`.

| Файл | Сущность 1С | Ключевые поля |
|---|---|---|
| `Catalog_Контрагенты.json` | Справочник «Контрагенты» | `Ref_Key`, `Code`, `Description`, `ИНН`, `КаналСбыта`, `Регион` |
| `Catalog_Номенклатура.json` | Справочник «Номенклатура» (группы — `IsFolder: true`) | `Ref_Key`, `Parent_Key`, `Артикул`, `Бренд`, `ЕдиницаИзмерения` |
| `AccumulationRegister_Продажи_Turnovers.json` | Обороты регистра «Продажи» по месяцам | `Period`, `Контрагент_Key`, `Номенклатура_Key`, `Регион`, `КоличествоTurnover`, `СтоимостьTurnover` (выручка), `СебестоимостьTurnover` |
| `InformationRegister_ПланМаржи.json` | Регистр сведений «План маржи» | `Period`, `Контрагент_Key`, `ГруппаНоменклатуры_Key`, `ПлановаяВыручка`, `ПлановаяМаржаПроцент` |

- Период продаж: 10.2025–09.2026, помесячно.
- Сезонность: пик в мае–августе, спад зимой.
- Себестоимость растёт быстрее отпускных цен: 0,5% против 0,4% в месяц.

## Формат подготовленной базы (SQLite)

| Таблица | Содержимое |
|---|---|
| `sources` | Источники наблюдений: сайты (B), прайс-листы (B), маркетплейсы (B), полевой мониторинг (C) |
| `competitors` | Конкуренты: ИНН, канал (свободный текст: «опт», «Оптовая торговля», «Дистрибьютор»…), дата регистрации, наличие регионального склада, схема поставок |
| `competitor_regions` | Присутствие в регионе: `first_seen`, `last_seen` (null — присутствует сейчас) |
| `offers` | Предложения конкурентов: артикул (заполнен ~70%), название, бренд, категория |
| `prices` | Наблюдения цен: еженедельно, 06.04.2026–19.10.2026 |

Данные намеренно «грязные», как после реального парсинга:
- регион записан по-разному: «Новосибирская область», «НСО», «г. Новосибирск»;
- цена — текстом: `1234.50`, `1 234,50 ₽`, `1 234 руб.`;
- у ~30% предложений нет артикула (иногда он есть в названии), названия бывают капсом;
- ~8% недель пропущено (страница недоступна);
- ~3% наблюдений продублированы полевым мониторингом с расхождением до ±2%.
