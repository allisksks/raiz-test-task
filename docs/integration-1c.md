# Интеграция с 1С

Данные забираются через **стандартный интерфейс OData** 1С: это REST-доступ к объектам базы, который есть в платформе 8.3 без доработки конфигурации. Если опубликовать базу на веб-сервере нельзя, загрузчик читает файлы выгрузки в том же формате.

## Что загружается

| Объект 1С | Куда в хранилище | Что берём |
|---|---|---|
| Справочник «Контрагенты» | `core.company` (kind = client), `core.company_region` | Наименование, ИНН, канал сбыта, регион |
| Справочник «Номенклатура» (группы и элементы) | `core.product_group`, `core.product` | Группа, артикул, наименование, бренд, единица |
| Обороты регистра «Продажи» по месяцам | `core.sales_fact` | Количество, выручка, себестоимость → маржа |
| Регистр сведений «План маржи» | `core.margin_plan` | Плановая выручка и маржа (%) по клиенту и группе товаров |

Как устроена загрузка:
1. **Сырые данные** сохраняются в `staging.onec_raw`. Они остаются, даже если загрузка упала, — по ним разбирают ошибку.
2. **Справочники** обновляются по GUID 1С (`Ref_Key`). Повторная загрузка не создаёт дублей.
3. **Продажи и план** за загружаемые месяцы заменяются целиком. Так исправления задним числом в 1С тоже попадают в хранилище.
4. **Изменения в `core`** пишутся одной транзакцией: при ошибке в хранилище ничего не меняется.
5. **Отклонённые записи** попадают в `staging.load_reject` с причиной: например, регион не распознан. Остальные записи загрузка не останавливают.
6. **Журнал запусков** ведётся в `staging.load_run`: статус, параметры, статистика, текст ошибки.

## Запуск

```bash
# Тестовая выгрузка (data/samples/onec) — по умолчанию, если не задан ONEC_ODATA_URL
market-map load-1c

# Другая папка с файлами выгрузки
market-map load-1c --path /mnt/exchange/1c

# Живая база: адрес и учётная запись — в .env
#   ONEC_ODATA_URL=http://1c-server/trade/odata/standard.odata
#   ONEC_USER=integration
#   ONEC_PASSWORD=...
market-map load-1c                       # текущий и два предыдущих месяца
market-map load-1c --from 2025-10 --to 2026-09   # первичная загрузка за год
```

В Docker: `docker compose run --rm app load-1c`. Для регулярного обновления достаточно запускать команду раз в сутки (cron или планировщик) — будут перезагружены последние три месяца.

## Подключение живой базы 1С

Делает администратор 1С заказчика.

1. **Опубликовать базу на веб-сервере** (Apache или IIS). В конфигураторе: *Администрирование → Публикация на веб-сервере*, отметить **«Публиковать стандартный интерфейс OData»**.
2. **Включить нужные объекты в состав OData.** Для этого в базе вызывается метод `УстановитьСоставСтандартногоИнтерфейсаOData()` или используется готовая обработка настройки OData. Нужны объекты из таблицы выше.
3. **Создать пользователя** для интеграции с правами только на чтение этих объектов.
4. **Проверить** в браузере: `http://<сервер>/<база>/odata/standard.odata/Catalog_Контрагенты?$format=json&$top=1`.
5. **Прописать адрес и учётную запись** в `.env`: `ONEC_ODATA_URL`, `ONEC_USER`, `ONEC_PASSWORD`.

## Адаптация к конфигурации заказчика

Тестовая выгрузка сделана в «идеальной» структуре. В типовых конфигурациях объекты называются иначе, а части полей нет. Имена сущностей собраны в одном месте — `src/market_map/integrations/onec/source.py`. Сопоставление полей — в `loader.py`.

Ориентиры для «Управления торговлей 11». **Их нужно проверить на базе заказчика:**

| В тестовой выгрузке | Вероятный аналог в УТ 11 |
|---|---|
| `Catalog_Контрагенты.Регион` | `Catalog_Партнеры.БизнесРегион` → `Catalog_БизнесРегионы` |
| `Catalog_Контрагенты.КаналСбыта` | Вид деятельности или сегмент партнёра; часто это доп. реквизит |
| `AccumulationRegister_Продажи` | `AccumulationRegister_ВыручкаИСебестоимостьПродаж` |
| `InformationRegister_ПланМаржи` | Планы продаж (`Document_ПланПродаж…`) или отдельный файл Excel |

Если плана маржи в 1С нет, его можно загрузить из файла в том же формате (`InformationRegister_ПланМаржи.json`).

Названия регионов распознаются по справочнику, с сокращениями «обл.», «кр.» и вариантами вроде «НСО» или «г. Москва» (`src/market_map/normalize.py`). Если в 1С регионы записаны по-своему, нераспознанные значения будут видны в `staging.load_reject`. Их добавляют в справочник вариантов в `src/market_map/reference.py`.
