# Перечень рабочих задач Market Map (после релиза 1.1.0)

Задачи расположены в порядке важности: сверху то, без чего продукт не работает или теряет доверие заказчика, ниже — развитие.

- **RUN** — поддержание работы того, что уже сдано: загрузки, данные, стенд, пользователи.
- **CHANGE** — изменения продукта: новые возможности, интеграции, улучшения.

| № | Тип | Задача | Почему важно | Результат |
|---|---|---|---|---|
| 1 | RUN | Ежедневный контроль ночной загрузки (`scheduler`, 03:00 МСК): журнал запусков, отклонённые записи, ошибки 1С и подготовленной базы | Без свежих данных карта, сигналы и гипотезы устаревают — продукт теряет смысл | Загрузка прошла или инцидент заведён до начала рабочего дня |
| 2 | RUN | Мониторинг свежести и достоверности источников (витрина `source_freshness`), реакция на просроченный источник | Решения по устаревшим ценам конкурентов ошибочны | Ни один источник не старше своей периодичности обновления |
| 3 | RUN | Резервное копирование PostgreSQL и проверка восстановления раз в неделю | Потеря истории цен необратима: её нельзя заново выгрузить | Ежедневный бэкап, протокол успешного восстановления |
| 4 | RUN | Разбор отклонённых записей и ручных сопоставлений товаров (`product_match`) | Несопоставленные товары выпадают из сравнения цен и сигналов | Доля несопоставленных позиций не растёт неделя к неделе |
| 5 | RUN | Поддержка пользователей дашбордов: доступы в Superset/Metabase, вопросы по сигналам и гипотезам | Аналитики должны пользоваться инструментом, а не обходить его | Обращения закрыты в течение рабочего дня |
| 6 | RUN | Обновления безопасности: базовые образы Docker, Superset, Metabase, зависимости Python; смена паролей по умолчанию | Стенд с паролями `admin/admin` и старыми образами уязвим | Ежемесячное обновление, CI зелёный |
| 7 | CHANGE | Подключение реальной базы 1С по OData вместо тестовых выгрузок | Сейчас сквозной сценарий работает на синтетике | Продажи и план маржи заказчика в хранилище |
| 8 | CHANGE | Уведомления о критичных сигналах (почта / Telegram) | Сигнал полезен, только если его увидели вовремя | Критичный сигнал приходит ответственному в день появления |
| 9 | CHANGE | Живые парсеры цен конкурентов (сайты, маркетплейсы Ozon/WB) через интерфейс `Source` | Подготовленная база обновляется редко и не покрывает рынок | Цены по ключевым конкурентам обновляются ежедневно |
| 10 | CHANGE | Калибровка весов гипотез по обратной связи аналитиков (подтвердилась / нет) | Сейчас все гипотезы сценария получают одинаковый score 0,85 | Гипотезы ранжируются по фактической точности |
| 11 | CHANGE | Тендерные площадки и ЕГРЮЛ как источники появления новых конкурентов | Новый конкурент виден раньше, чем по ценам | Сигнал «новый конкурент» по данным ЕГРЮЛ/ЕИС |
| 12 | CHANGE | Прогноз долей рынка (ML) вместо оценки по прошлым периодам | Повышает достоверность `estimate` | Доли с доверительным интервалом и пометкой `estimate` |
| 13 | CHANGE | Выбор одной BI (Superset или Metabase) по итогам демо и вывод второй из эксплуатации | Две BI удваивают затраты на поддержку (RUN 5, 6) | Одна BI в проде, вторая удалена из `docker-compose.yml` |

## Как читать порядок

1. **Сначала RUN 1–4.** Это «гигиена данных»: если ночная загрузка упала или история потеряна, любые CHANGE-задачи строятся на неверных цифрах.
2. **RUN 5–6** — непрерывные задачи с небольшим объёмом, их не откладывают ради развития.
3. **CHANGE 7** — главная задача развития: без реальных данных 1С продукт остаётся демо.
4. **CHANGE 8–13** — по убыванию ценности для заказчика. Задача 13 снижает будущую RUN-нагрузку, поэтому её стоит решить сразу после обратной связи по демо.
