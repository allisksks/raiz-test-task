# Перечень рабочих задач AI-команды

Микрокоманда сопровождает AI-продукт: LLM-ассистент для сотрудников (ответы по базе знаний, RAG) и ML-модели прогноза. Задачи расположены в порядке важности.

- **RUN** — поддержание работы того, что уже в эксплуатации.
- **CHANGE** — изменения: новые возможности, модели, сценарии.

| № | Тип | Задача | Почему важно | Результат |
|---|---|---|---|---|
| 1 | RUN | Мониторинг доступности и задержки LLM-ассистента и API провайдера модели | Ассистент недоступен — сотрудники остаются без инструмента | Доступность ≥ 99,5%, инциденты заведены в течение 15 минут |
| 2 | RUN | Контроль безопасности: утечки персональных данных и коммерческой тайны в запросах, prompt injection, фильтры ответов | Одна утечка или вредный ответ стоят дороже всей пользы от AI | Ежедневный разбор срабатываний фильтров, ноль утечек |
| 3 | RUN | Регулярная оценка качества ответов на эталонном наборе вопросов (evals): точность, галлюцинации, ссылки на источники | Качество незаметно падает при смене модели, промпта или данных | Еженедельный отчёт, откат при падении метрик |
| 4 | RUN | Обновление базы знаний для RAG: переиндексация документов, удаление устаревших | Ассистент отвечает по старым регламентам | Индекс отстаёт от источников не более чем на сутки |
| 5 | RUN | Мониторинг дрейфа данных и точности ML-моделей прогноза, плановое переобучение | Модель, обученная на прошлом рынке, ошибается всё сильнее | Ошибка прогноза в пределах порога, переобучение по графику |
| 6 | RUN | Контроль затрат на токены и GPU, лимиты по командам | Расходы на AI растут быстрее пользы | Бюджет месяца не превышен |
| 7 | RUN | Разбор обратной связи пользователей (👍/👎, жалобы) | Главный источник реальных ошибок | Обращения разобраны, частые ошибки попадают в evals |
| 8 | CHANGE | Переход на новую версию модели после сравнения на evals | Новая модель лучше и дешевле, но может сломать сценарии | Миграция без падения метрик качества |
| 9 | CHANGE | AI-агент с доступом к рабочим системам (CRM, 1С, тикеты) с подтверждением действий человеком | Переход от «отвечает» к «делает» — основной рост ценности | Пилот на одном процессе, логирование всех действий |
| 10 | CHANGE | Автоматизация рутинных процессов: суммаризация встреч, черновики писем, классификация обращений | Быстрый измеримый эффект в часах сотрудников | 3 сценария в эксплуатации, экономия времени измерена |
| 11 | CHANGE | Политика ответственного использования AI и обучение сотрудников | Без правил люди отправляют в AI конфиденциальные данные | Политика утверждена, обучение пройдено |
| 12 | CHANGE | Дообучение или адаптация модели под термины компании | Улучшает качество там, где не помогает RAG | Прирост метрик на evals доменных вопросов |
| 13 | CHANGE | Мультимодальность: разбор сканов, фото, голосовых запросов | Расширяет круг задач | Пилот на одном типе документов |

## Как читать порядок

1. **RUN 1–3** — доступность, безопасность и качество. AI, который недоступен, небезопасен или галлюцинирует, вредит больше, чем помогает.
2. **RUN 4–7** — то, что не даёт системе деградировать: данные, модели, деньги, обратная связь.
3. **CHANGE 8** идёт первой среди изменений: модели устаревают быстро, а evals из RUN 3 делают переход безопасным.
4. **CHANGE 9–13** — по убыванию ценности. Задачу 11 стоит запустить параллельно с 9: агенту с доступом к системам нужны правила до запуска.
